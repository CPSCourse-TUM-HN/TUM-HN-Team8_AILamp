# OpenAI 大脑与无音频交互重构设计

日期：2026-09-05。本文是本轮实现与验收的设计依据，不是 Jetson 真机验收报告。

## 已确认的边界

用户确认 Jetson Nano、5 个 ST3215 舵机、LED 灯板和 USB 摄像头都已装好；舵机 ID、校准及 LeLamp 动作回放已完成且能正常运行。目前没有麦克风和扬声器。用户选择 OpenAI 作为 AI 大脑，并要求删除生日灯光提醒。

保留现有机械结构、校准、动作录制及 LeLamp 公共控制接口；不改 CAD、不重新校准、不推送 Git、不自动部署到 Nano，也不在开发机器上连接硬件或调用收费模型。

## 方案选择

主方案是多模态 AI 大脑：OpenAI 综合文字、可选摄像头图像、台灯状态和执行反馈，决定调用动作工具。纯按钮遥控与固定规则都不能替代这个主方案：按钮仅用于调试和离线备用；旧视觉规则入口保留兼容，但不作为新 AI 能力的证明。

```text
网页自然语言 ───┐
USB 摄像头画面 ├──→ OpenAI：理解情境、提出工具计划
状态与近期反馈 ┘                  │
                                  ↓
                     本地执行检查：白名单、有限参数、
                     解锁状态、时效、停止代次、忙碌状态
                                  │
                       ┌──────────┴──────────┐
                       ↓                     ↓
                LeLamp 舵机执行器       Pico 灯光控制
                       └──────────┬──────────┘
                                  ↓
                 已接收 / 执行中 / 已完成 / 错误反馈
                    → 网页显示，并进入下一次 AI 上下文
```

AI 不输出 Python、串口字节或任意硬件命令。它调用受约束的 `play_recording`、`move_joints`、`set_light`、`set_mode`、`do_nothing` 工具。工具范围包含真实关节微调，而非只能播放固定表情。模型可以选择不动作。

## 当前可实现的交互

| 原交互目的 | 无音频版本 |
| --- | --- |
| 对台灯说出意图 | 在网页输入自然语言，交给 OpenAI 理解 |
| 台灯回应用户 | 网页短文字、灯光和机械动作 |
| 观察人或手势并反应 | 用户显式开启摄像头后，由同一个 AI 看图决策 |
| 跟随与性格动作 | AI 选择小步关节微调或白名单动作；不能声称是硬实时跟踪 |
| 专注陪伴与休息 | AI 或手动选择模式，专注计时结束后转休息灯光，无声音 |
| 生日提醒 | 从当前运行代码、命令、配置、定时服务及入口删除 |

“看着我”“用动作表示开心”“我想专心学习，请安静陪着我”都应送入真实模型，而不是通过关键词映射伪装理解。未配置 API 或未启用大脑时，界面明确说明 AI 不可用，仍允许使用离线调试按钮。

## 运行与物理动作边界

默认本地网页是预览：不开摄像头、不连接串口、不调用 API。`--brain` 明确启用 OpenAI；`--vision` 明确允许使用摄像头并发送画面；`--with-outputs` 允许连接真机，网页还需人工解锁后才能执行输出。模型不能自行解锁。

一次只处理一个 AI 请求，并限制调用间隔和总调用数。摄像头图片只用于本次请求，不默认写入磁盘。API 密钥仅从正常环境配置读取，不进入网页、日志或版本库。

每次请求记录控制代次和时间。停止、手动接管、上锁、模式切换都使旧请求失效。即使 OpenAI 随后成功返回，过时代次的计划也必须丢弃。模型超时、缺帧、过期图像和不合法工具计划不得转成自动扫描动作。

软件停止取消未来轨迹帧并保持当前目标/扭矩，不等同于切断电源的硬件急停；运行实物时需要保留物理断电能力，并避免手进入关节夹点。

## 坐标与执行反馈

当前 LeLamp 录制和 follower 默认使用 LeRobot 的归一化关节坐标 `[-100,100]`，不是物理角度。AI 单次微调每个关节最多正负 4 个归一化单位；底层还需分步发送并限制目标变化。旧字段名 `delta_deg` 仅兼容旧接口，不得继续把它解释成度。

连接时读取已有校准下的初始观测，不自动播放 idle，也不重新校准。后续发送目标不冒充实时位置测量。`accepted` 不等于已完成；动作完成需等待 worker 空闲且没有错误。一个进程内只有一个 motor worker 写总线。新服务间使用串口互斥；不遵循该锁的旧 LeLamp 进程仍需用户先停止。

## 验收层次

1. 单元测试：不合法工具、越界和非有限数、路径白名单、音频关闭、生日移除。
2. 集成测试：自由文字和图像传给模型边界；受检计划到舵机/灯光；停止后迟到结果无效；并发、过期、预算、清理失败和软件停止。
3. 网页测试：预览/真机/AI 状态真实；无密钥泄露；请求认证、来源与输入检查；可见错误和动作状态。
4. Nano 验收：在用户已能运行 LeLamp 的环境中，核对 Python、follower 导入、校准 ID、串口及 Pico 协议，然后依次做 AI 只读/干跑、灯光、单个小动作、图像闭环。本文不宣称这些真机步骤已通过。

## 部署约束

AILamp 自身要求 Python 3.11 以上，而当前本地上游 lelamp_runtime 声明 Python 3.12 以上。应先核对并复用已正常运行的 Nano 环境，不能依据旧文档盲目新建 Python 3.11 环境或全量升级依赖。模型默认沿用已有 `gpt-4.1-mini` 配置，并可调整；AI 能力与响应速度须现场验证。
