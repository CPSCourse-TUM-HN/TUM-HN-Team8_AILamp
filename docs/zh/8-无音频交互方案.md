# 8. 无音频交互方案

## 已确认设备

你已确认 Nano、5 个舵机、LED 灯板和 USB 摄像头已装好，舵机已设置 ID、完成校准，LeLamp 动作能正常运行。软件优先复用已有接线和动作环境，不主动覆盖校准。

仓库目前按 Jetson Nano 4GB、ST3215 舵机和 Pico WH 控制的 8x8 LED 面板配置。具体串口、已有 follower ID，以及 LED 是否使用本仓库的 Pico 串口协议，仍须在 Nano 上核对；配置文件不是实物检测结果。

| 项目 | 状态 |
|---|---|
| LeLamp 灯臂、灯头、柔光罩 | 保留 |
| ST3215 动作录制 | 保留，单位是 LeRobot/LeLamp 归一化 `.pos`，不是物理角度 |
| OpenAI brain | 当前主路径，默认模型 `gpt-4.1-mini` |
| USB 摄像头 | 可选加入 brain 上下文 |
| 手动按钮 | 仅用于调试/验收，不替代 AI |
| 麦克风、扬声器、LiveKit 语音 | 当前默认配置禁用，仅作为未来升级 |
| 生日提醒 | 已从活动 runtime、配置、CLI、systemd 和文档中移除 |

## AI-BRAIN 架构

```text
用户文字 + 可选摄像头 JPEG + 状态/历史
  -> OpenAI BrainService 真实模型调用
  -> 工具计划 play_recording / move_joints / set_light / set_mode / do_nothing
  -> 本地严格验证和输出闸门
  -> 统一串行的 LampController 准入 + 单个电机 worker 执行
  -> 接收/发送/完成/错误结果写回下一次 AI 上下文
```

没有 `--brain` 时，自由文本输入会明确显示 AI 不可用，不会用关键词规则假装推理。`vision-loop` 是旧兼容路径，会把视觉事件映射到固定动作；新的主路径不会再并行跑视觉分类再套规则，而是把 JPEG 直接给 brain。

## 先准备什么

以下命令在 **Nano 的终端**执行，先进入 AILamp 仓库并激活已经能运行 LeLamp 动作的 Python 环境。若只是电脑上看界面，可用普通 Python >=3.11 环境，不需要连接台灯。

按 `docs/zh/4-运行环境.md` 安装运行包。不要为此重新刷系统或覆盖校准；如果依赖安装提出与现有 LeLamp 环境冲突的要求，先停止安装并检查版本。

在 `config/hardware.toml` 核对这四项：

| 配置项 | 应填写的内容 |
|---|---|
| `motors.lamp_id` | 之前成功运行 LeLamp 时使用的同一个 follower ID，不是随便给灯起的新名字 |
| `motors.port` | 舵机控制板在 Nano 上的串口路径 |
| `led.port` | Pico LED 控制器在 Nano 上的串口路径 |
| `camera.device_path` | USB 摄像头的视频设备路径 |

把 OpenAI API key 放在 Nano 的 `OPENAI_API_KEY` 环境变量中；不要提交到 Git，也不要填写到网页 LAN 令牌栏。下文命令中的 `OPENAI_API_KEY=...` 是占位示意，不是可用密钥。

## 运行方式

先 dry-run，不打开摄像头、不连串口、不调用云端：

```bash
ailamp web-control
```

在运行服务的电脑上打开 `http://127.0.0.1:8765`。网页应显示“演示模式 / AI 未启用”。此时点击调试按钮只改变虚拟状态，不会让实物运动；向 AI 发文字会明确报告未启用。

启用文字 brain：

```bash
OPENAI_API_KEY=... ailamp web-control --brain
```

启用文字 + 摄像头 brain。摄像头帧会发送给配置的 OpenAI 模型，可能产生费用并涉及隐私：

```bash
OPENAI_API_KEY=... ailamp web-control --brain --vision
```

真机输出只在硬件检查通过后启用，并且浏览器里还要点击解锁：

```bash
OPENAI_API_KEY=... ailamp web-control --brain --vision --with-outputs
```

默认监听 `127.0.0.1:8765`。若服务运行在 Nano、你使用自己的电脑浏览，推荐在**自己的电脑终端**打开 SSH 隧道（替换用户名和 Nano IP），保持该终端开启，再访问上面的本机网址：

```bash
ssh -N -L 8765:127.0.0.1:8765 nano用户名@Nano的IP地址
```

也可以在可信局域网直接访问，但 Nano 上必须绑定具体 IP 并设置强令牌；下面的 `192.168.1.50` 只是示例，应替换为 Nano 的实际 IP：

```bash
python3 - <<'PY'
import secrets
print(secrets.token_urlsafe(32))
PY
export AILAMP_CONTROL_TOKEN='把上一步生成的令牌粘贴到这里'
OPENAI_API_KEY=... ailamp web-control --host 192.168.1.50 --brain --vision --token-env AILAMP_CONTROL_TOKEN
```

不要绑定 `0.0.0.0`，也不要暴露到公网。真机输出前，先停止原 LeLamp playback、`vision-loop` 或 voice-agent 等可能占用舵机串口的进程。

局域网访问时，在网页“LAN 控制令牌”栏粘贴你生成的令牌，不要粘贴 OpenAI API key。令牌不同，用途也不同。

## 在网页里怎么用

1. **先测试文字大脑，不启用真机输出。** 用 `--brain` 启动，输入“我想学习 25 分钟，请保持安静并调成暖光”。查看回复和工具计划的虚拟执行结果。
2. **再测试视觉。** 加上 `--vision` 后，文字请求也会附带新获取的相机画面；“AI 观察一次”用于单次观察。“开启自动观察”才会持续进行低频决策，可能持续产生 API 费用。
3. **最后才接管实物。** 停止其他控制程序，核对串口、校准身份和 LED 协议，在人员看护、灯臂周围无障碍且可切断电机供电的条件下，用 `--with-outputs` 启动，再点“解锁真机输出”。先验收已知动作和灯光，再测试 AI。
4. **随时接管。** “非 AI 调试控件”用于人工验收；手动操作会关闭自动观察。红色“软件停止”使旧 AI 请求失效并锁定输出，重新解锁不应让旧请求复活。

`accepted / sent / completed` 分别表示接受请求、向执行服务提交、服务报告执行结束；“完成”不等于用传感器证明灯臂到达目标位置。没有实测反馈时，界面关节值是初始观测或已发送目标值，不能当作连续测量。

## 硬件与环境边界

AILamp 包本身支持 Python >=3.11 做软件预览；但本仓库旁边的上游 LeLamp runtime 目前要求 Python >=3.12。不要盲目升级系统 Python 或覆盖校准，优先复用已经能播放动作的环境。

```bash
scripts/check_jetson_nano_environment.sh
ailamp runtime-check --offline
ailamp runtime-check --include-motor-runtime
ailamp hardware-check --include-devices
ailamp led-test
ailamp motor-test
```

`motors.lamp_id` 必须改成这台 Nano 上已经成功播放 LeLamp 动作的准确 follower ID；默认 `ailamp` 只是配置默认值，不证明已有校准身份。`ailamp motor-test` 只列出配置端口和 bundled recordings，不移动硬件，也不证明真实动作通过。Pico WH 需要先刷入 `firmware/pico_led_controller/code.py`，并确认 `PING`、`SOLID`、`BRIGHTNESS`、`CLEAR` 协议正常。

## 现实限制

OpenAI brain 是低频决策，不是硬实时伺服闭环，也不是瞬时视觉跟踪。OpenCV 时间戳是主机采集时间，不是 USB 硬件曝光时间；真实 USB buffering 延迟没有在本机测试中测量。每步关节增量限制只是归一化单位保护，不是碰撞避免。开启摄像头的 brain 模式会把 JPEG 发给 OpenAI；本地测试使用 fake，不产生云端费用。

软件停止会取消后续动作并使旧请求失效，但电机仍可能完成最后一次已下发的小步目标；它不是机械制动或物理断电。实物验收前必须确保有人能立即切断电机 12V 供电，不要假设网页按钮能够代替物理急停。

当前交付尚未在你的 Nano 上完成真实 OpenAI 调用、摄像头延迟或整机联合验收。2026-09-05 已修复 `uv.lock` 与 `pyproject.toml` 的 extras 不一致：`nano` 不再包含 LiveKit、降噪插件和 `sounddevice`，`hardware` 不再包含 `sounddevice`，而 `voice` 保留这些音频依赖。音频包仍会出现在支持多个安装选项的完整锁文件中，这不代表选择 `nano` 时也会安装它们。

经用户授权使用独立临时缓存，并允许更新子进程访问 PyPI 及官方包下载源后，正常 `uv lock` 和 `uv lock --check` 均已通过。130 个锁定包的版本保持不变，变更仅限本项目的 extras 及对应依赖元数据。

本次未修改原缓存权限，未执行安装或 `uv sync`，也未修改 Nano 配置与硬件控制参数。锁文件一致性检查通过不能替代 Nano 安装兼容性及整机验收。

如果关闭程序时报资源清理错误，不要直接启动第二个控制程序接管串口。先确认旧进程已退出、串口已释放，再排查。正在进行的请求关闭等待超时可再次关闭；普通资源清理异常不保证在同一 runtime 对象中自动重试。
